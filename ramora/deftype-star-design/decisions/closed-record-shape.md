# deftype* decisions: closed record shape

Each decision is d = ⟨subject, choice, rejected, rationale, qualities,
commitment⟩. Commitment: `firm` or `provisional` (change when evidence
requires it). The [decision index](../decisions.md) lists all decisions.

## D9. Select the closed record shape with an option (interface)

- Choice: the `deftype*` option `:value-type/closed`, in the option
  position after the fields. `true` selects the closed shape. `false`, `nil`
  and an absent option do not select it; the form keeps its plain or record
  shape. Other values give `:invalid-option` with `:option`, `:value` and
  `:reason :invalid-value`. `true` on a plain-shape form gives
  `:invalid-option` with `:reason :record-shape-required`. When the option
  occurs more than once in the option position, the last occurrence
  applies, as in `deftype*`; the checks examine only its value. The checks
  run after `:record-shape` and before the metadata keys (public-contract
  order). `defvaluetype*` removes each occurrence of the option, for each
  value, from the `deftype*` call. The receiving macros get the option in
  the form, repeat the checks and remove each occurrence from their
  `deftype*` call.
- Rejected:
  - Infer the closed shape, for example from a type that does not
    implement `IObj`. A change of the interface list would then change the
    layout and the constructor contract with no signal.
  - Metadata on `__meta` or `__extmap`. D2 fixes the hidden-field
    metadata, and one shape would need two markers.
  - A separate macro. It duplicates the `defvaluetype*` contract for one
    flag.
  - An unqualified option name. `deftype*` options are unqualified and
    owned by Clojure (`:implements`, `:tag`, `:load-ns`); a qualified key
    cannot collide with them.
- Rationale: `deftype*` accepts keyword options and ignores unknown keys
  (`Compiler.DeftypeParser`). An option keeps the form one-to-one with
  `deftype*` (D1), and it is explicit.
- Improves: explicitness, minimality. Degrades: the `deftype*` call is no
  longer exactly the macro arguments; one option is removed.
- Commitment: provisional (first caller: closed-record).

## D10. Closed record shape: no metadata and no extension map (state and behaviour)

- Choice: for the closed shape:
  - Value output removes `__meta`, `__extmap`, `__hash` and `__hasheq`.
    Constructors keep their descriptors (D3). The D4 access check covers
    all four fields.
  - Identity output keeps all four fields.
  - In both outputs, the main constructor throws `IllegalArgumentException`
    for a non-nil `__meta` or `__extmap` argument, before the non-nil field
    checks (D8). Error text is not specified.
  - Check sites. Value output: the main-constructor rewrite of D3 and D8
    adds the check. Identity output: the identity backend gets the shape.
    For the closed shape, it adds the check at the entry of each
    non-delegating constructor (D8) of the target class, before the first
    original instruction. The check reads `__meta` and `__extmap` as the
    parameters at index n − 4 and n − 3, where n is the parameter count of
    that constructor. The backend processes the constructors of a closed
    form also when the form has no enabled fields. A non-delegating
    constructor with fewer than four parameters or with a parameter at
    n − 4 or n − 3 that is not of type `Object`, and a closed class with no
    non-delegating constructor, give `:unsupported-shape`. In compiler
    output, the main constructor is the only non-delegating constructor.
  - A closed form needs a transform in both outputs, so it uses the
    receiving expansion and the identity backend, as forms with enabled
    fields do (D5, D8).
- Rejected:
  - Remove the fields and ignore their arguments. A map literal with an
    undeclared key would then lose the key with no signal.
  - Remove the fields from identity output too. Identity output does not
    flatten, and the D4 rationale applies.
  - Throw `ex-info` with `:value-type/error`. The non-nil checks use host
    exceptions, and the check is in generated bytecode on Java 8 too.
  - Check only `__extmap`. The constructor with meta and extmap is public; a
    Java caller could then set metadata that value output does not keep.
  - Keep the fields and make the class loosely consistent
    (`@LooselyConsistentValue`) with non-atomic arrays. Data races can then
    tear values, the annotation is internal to the JDK, and each element
    keeps two reference slots.
- Rationale: `create` passes nil for `__meta`, and nil for `__extmap` unless
  the map has an undeclared key ([Context](../context.md)). Thus one check in
  the main constructor rejects undeclared keys on all `create` paths and
  accepts all other paths. A record with no metadata and no extension keys has only its
  declared fields, so small records can flatten.
- Improves: layout (8 more bytes removed per value instance; flattening of
  records with at most 64 bits of fields on the observed JVM). Degrades:
  closed types have no metadata and no extension keys; identity output
  needs a transform; the error has no `ex-data`.
- Assumption: the closed gate (D7) passes.
- Commitment: firm (D7 closed gate passed).
