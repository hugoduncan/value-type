  passes 1 test / 18 assertions. The children explicitly use EA3 preview, all

## Next concrete work

1. Extend public stale-loader rejection to fresh silent/warn/error receivers,
   preserving the distinction between strict identity-policy rejection and a loader
   failure reached during permitted compilation. Include preview-enabled generated
   value owners so strict policy can reach the loader boundary.
2. Exercise real unsupported input through capture and public compilation where
   the public declaration grammar permits it. Verify the structured failure/cause,
   absence of an installed owner/factory, and absence of weaker retry output.
3. Keep malformed probe helper evidence separate from detector/public evidence.
   Do not add probe mocks or broaden the approved native-absence accessor override
   to manufacture defects. Document any boundary that cannot be reached with real
   declarations rather than claiming public coverage from helper tests.

General attribute preservation and hierarchy resolution remain separate work.
No production defect was established by this audit; no API, dependency or design
contract change is required.

## Fresh-policy public loader verification

`loader-policy-test/fresh-policy-loader-rejection-test` runs the existing public
stale-import test in 14 isolated JVMs. Java 8 and preview-disabled EA3 use silent
and warn; preview-enabled EA3 also uses error. Each runs normally and with `-Xint`.
Both expansion entries and eval/function/source analysis reject twice with structured
errors, no receiving warning and no owner/factory installation; corrected imports
permit all three constructor entries. No mocks or production changes are used.

With the documented EA3 JAVA_CMD, `clojure -M:fallback-test --namespace
value-type.loader-policy-test` exits 0: 1 test / 42 assertions, empty failure
results. Log: `/tmp/task017-loader-policy.log`. Scoped cljfmt and clj-kondo pass.
This completes next-work item 1 above. Strict baseline policy rejects before the
loader boundary and is not included as loader-failure evidence. Selection-time
warn output is permitted; the inner test checks empty stderr during rejection.
Real capture failures and public probe propagation remain separate gaps.

## Real identity capture shape rejection

`capture-failure-test/unsupported-owner-capture-test` sends real class bytes with
missing selected storage through the production capture loader. Two definitions
on the same loader retain `:unsupported-shape`; class lookup fails after each
attempt and stderr stays empty. No mocks or production switches are used.

On 2026-10-27, `clojure -M:fallback-test --namespace
value-type.capture-failure-test` passes 1 test / 5 assertions on Java 8 and EA3
preview off/on, each normally and with `-J-Xint`. Each CLI exit is 0 with an empty
`.scry-results` directory. EA3 preview uses `-J--enable-preview`. Scoped cljfmt
and clj-kondo pass.

This exercises identity capture explicitly, even on a value-capable host. It does
not establish value-backend, public declaration or all-policy failure coverage.
Missing selected storage is not emitted by an ordinary valid public declaration;
the test supplies unsupported bytes at the capture boundary instead. Public
reachable failures and the other failure classes remain separate follow-ups.
